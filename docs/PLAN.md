# LinguaKids — Web App ฝึกภาษาอังกฤษสำหรับเด็กอนุบาล–ประถม

เอกสารแผนงานฉบับที่ 1 · 1 พ.ย. 2026 · สถานะ: รออนุมัติ / เพิ่มเติมจากเจ้าของโปรเจกต์

---

## 1. ข้อสังเกตสำคัญก่อนเริ่ม (อ่านก่อน)

**เรื่องเป้าหมาย C1** — C1 ตามกรอบ CEFR คือระดับที่ใช้ภาษาเชิงวิชาการ/วิชาชีพได้อย่างคล่องแคล่ว และเป็นเป้าที่เด็ก ป.6 (อายุราว 12 ปี) แทบไม่มีระบบไหนในโลกพาไปถึงได้ ถ้าไม่ใช่โรงเรียนอินเตอร์แบบ immersive เต็มเวลา ผมจึงเสนอให้แยก 2 เรื่องออกจากกัน:

| | เป้าหมาย |
|---|---|
| **เป้าของตัวเด็ก (realistic)** | อนุบาล = Pre-A1 · ป.1–2 = A1 · ป.3–4 = A2 · ป.5–6 = A2+/B1 |
| **เป้าของตัวระบบ (ที่เราจะสร้าง)** | curriculum ladder + engine ที่ **ไต่ต่อได้จนถึง C1** ไม่มีเพดาน เด็กเก่งเรียนล่วงหน้าได้ และใช้ต่อกับ ม.ต้น–ม.ปลาย ได้โดยไม่ต้องรื้อระบบ |

แบบนี้ได้ทั้ง "อ้างมาตรฐานสากลได้จริง" และ "ไม่โฆษณาเกินจริงกับผู้ปกครอง" ซึ่งสำคัญถ้าจะนำไปเสนอหรือใช้จริง

ถ้าคุณยืนยันว่าอยากตั้งเป้า C1 ที่ตัวเด็กเลย ผมทำตามได้ครับ แค่จะวาง ladder ให้ยาวกว่านี้ โหลดเนื้อหาหนักกว่านี้มาก และต้องทำ placement test ให้ละเอียดขึ้น

**เรื่องเสียงพูด** — การ "ให้คะแนนการออกเสียง" ที่แม่นระดับหน่วยเสียง (phoneme) ต้องใช้ API เชิงพาณิชย์ (Azure Pronunciation Assessment / Speechace / ELSA) ส่วน Web Speech API ที่ฟรีในเบราว์เซอร์บอกได้แค่ว่า "ถอดเสียงออกมาเป็นคำว่าอะไร" ใช้ทำ MVP ได้ แต่ไม่พอสำหรับฟีดแบ็กรายหน่วยเสียง → เป็นข้อตัดสินใจ D2 ในหัวข้อ 15

## 2. กลุ่มผู้ใช้ และสิ่งที่แต่ละคนต้องได้

| ผู้ใช้ | ต้องการ |
|---|---|
| เด็กอนุบาล (4–6) | ยังอ่านไม่ออก → UI ต้องเป็นไอคอน + เสียง ปุ่มใหญ่ ไม่มีการพิมพ์ ไม่จำกัดเวลา |
| เด็กประถมต้น (7–9) | อ่านคำสั้นได้ → เริ่มพิมพ์/ลากคำ มีการแข่งกับตัวเอง |
| เด็กประถมปลาย (10–12) | อ่านประโยคได้ → แชทกับ AI, อ่านออกเสียงเรื่องสั้น, เขียนประโยค |
| ผู้ปกครอง | เห็นว่าลูกเล่นอะไร เก่งขึ้นไหม ใช้เวลาเท่าไร ตั้งลิมิตเวลาได้ |
| ครู | สร้างห้องเรียน แจก class code ดูคะแนนรายคน/รายคำ สั่งการบ้าน พิมพ์ worksheet |

**หลักการออกแบบสำหรับเด็ก (ยึดเป็นกฎ)**

1. ทุกข้อความบนจอต้องกดฟังเสียงได้ (เด็กอนุบาลอ่านไม่ออก)
2. ไม่มีการตอบ "ผิด" แบบลงโทษ — ผิดคือ "ลองอีกครั้ง" พร้อมเฉลยแบบสอน
3. 1 หน้าจอ = 1 งาน ไม่มีเมนูซ้อนเมนู
4. เซสชันละ 3–7 นาที (ช่วงความสนใจของเด็ก) แล้วปิดด้วยรางวัล
5. ภาษาไทยช่วยได้ตอนต้น แล้วค่อย ๆ ถอด scaffold ออกตามระดับ

## 3. โหมดการเล่น

### 3.1 ที่คุณระบุมา (ต้องมี)

| # | โหมด | รายละเอียดที่ผมเสนอ |
|---|---|---|
| G1 | **AI Chat Buddy** (พูดคุยกับ AI) | เด็กกดปุ่มไมค์แล้วพูด → ถอดเสียง → โมเดลภาษาตอบเป็นข้อความ + เสียงพูด (TTS) พร้อมมาสคอตที่ขยับได้ ควบคุมระดับคำศัพท์ตาม CEFR ของเด็ก มีปุ่ม "แปลเป็นไทย" และ "พูดช้า ๆ อีกครั้ง" และ AI จะถามกลับทุกครั้งเพื่อให้บทสนทนาไม่ตาย |
| G2 | **Fill in the Blank** (เติมคำที่ขาด) | 3 ระดับความยาก: (ก) เลือกจากคลังคำ 3 ตัว (อนุบาล) (ข) ลากตัวอักษรมาต่อ (ประถมต้น) (ค) พิมพ์เอง + ตรวจแบบใจดี (สะกดผิด 1 ตัวให้คำใบ้ก่อน ไม่ตัดถูกผิดทันที) |
| G3 | **Match EN ↔ TH** (จับคู่คำ) | 2 คอลัมน์ลากเส้นจับคู่ + โหมด Memory Flip (เปิดการ์ดหาคู่) เป็นข้อมูลชุดเดียวกันแต่คนละหน้าตา ทำให้เล่นซ้ำได้ไม่เบื่อ |
| G4 | **Picture Word** (ดูภาพเติมคำ) | เห็นภาพแล้ว (ก) เลือกคำ (ข) สะกดด้วย letter tiles (ค) พูดชื่อสิ่งนั้นออกเสียงให้ STT ตรวจ — ภาพเดียวใช้ฝึกได้ 3 ทักษะ |

### 3.2 ที่ผมเสนอเพิ่ม (เรียงตามความคุ้มค่า)

| # | โหมด | ทำไมควรมี |
|---|---|---|
| G5 | **Say It! — ให้คะแนนการออกเสียง** | หัวใจของ "พูดได้จริง" เด็กพูดตามคำ/ประโยค ระบบให้ดาว 1–3 ดวง + บอกว่าหน่วยเสียงไหนเพี้ยน เช่น /θ/ ใน *three* ซึ่งเป็นจุดอ่อนคลาสสิกของคนไทย (th, v, l/r, เสียงท้ายคำ -s, -ed) |
| G6 | **Read Aloud — อ่านออกเสียงเรื่องสั้น** | ตอบโจทย์ "ฝึกอ่าน" โดยตรง มี graded reader ไฮไลต์คำแบบคาราโอเกะตามที่เด็กอ่าน วัดความถูกต้อง + คำต่อนาที (WPM) + ความลื่นไหล |
| G7 | **Listen & Choose** | ฟังเสียงแล้วเลือกภาพ/คำ ฝึกทักษะฟังซึ่งเด็กไทยอ่อนที่สุด และเป็นด่านที่เล่นได้แม้ยังอ่านไม่ออก เหมาะกับอนุบาลมาก |
| G8 | **Sentence Builder** | ลากการ์ดคำมาเรียงเป็นประโยค สอนไวยากรณ์และลำดับคำ (จุดที่โครงสร้างไทยต่างจากอังกฤษ) โดยไม่ต้องท่องกฎ |
| G9 | **Phonics Lab** | สอนเสียงตัวอักษร (a-a-apple), blends, rhyming words — ฐานรากของการอ่านออกเอง ขาดไม่ได้สำหรับอนุบาล–ป.1 |
| G10 | **Story Quest (ด่านบอส)** | เรื่องผจญภัยสั้นที่เด็กต้องพูดโต้ตอบกับตัวละครเพื่อผ่านด่าน = role-play จริงจัง จบ 1 unit ต่อ 1 quest ทำให้รู้สึกว่ามีเป้า ไม่ใช่ทำแบบฝึกหัดเปล่า ๆ |
| G11 | **Odd One Out / Category Sort** | จัดคำเข้าหมวด (สัตว์/ผลไม้/สี) ฝึกการจัดกลุ่มความหมาย ซึ่งช่วยการจำคำศัพท์ระยะยาว |
| G12 | **Daily Challenge (ด่านทบทวน)** | SRS ดึงคำที่ "ใกล้ลืม" มาสร้างด่านใหม่ทุกวัน = เครื่องยนต์ที่ทำให้ความรู้ไม่หล่นหาย |

## 4. Learning Engine (ส่วนที่ทำให้ "เรียนได้จริง" ไม่ใช่แค่เกมสนุก)

นี่คือส่วนที่แอปเรียนภาษาคุณภาพต่ำไม่มี และเป็นเหตุผลที่ Duolingo ได้ผล

1. **Spaced Repetition (FSRS)** — ทุกคำและทุกโครงสร้างเป็น "การ์ด" ที่มีค่า stability/difficulty ระบบคำนวณว่าควรเจอคำนี้อีกเมื่อไร แล้วสร้างด่านทบทวนรายวันจากคิวนี้
2. **Mastery ต่อรายการ (0–5 ดาว)** — คำหนึ่งต้องผ่านหลายรูปแบบ (เห็นแล้วจำได้ / ฟังแล้วเข้าใจ / พูดถูก / เขียนถูก) จึงนับว่า "รู้จริง" ไม่ใช่ตอบถูกครั้งเดียวแล้วผ่าน
3. **Adaptive difficulty (Elo)** — ทั้งเด็กและข้อสอบมีคะแนน Elo ตอบถูกข้อยากได้คะแนนเยอะ ระบบเลือกข้อที่เด็กมีโอกาสถูกราว 75–80% ซึ่งเป็นโซนที่เรียนรู้ได้ดีที่สุด (ไม่ง่ายจนเบื่อ ไม่ยากจนท้อ)
4. **Placement test** — 12–15 ข้อแบบ adaptive ตอนสมัคร เพื่อไม่ให้เด็ก ป.5 ต้องเริ่มจากคำว่า apple
5. **Error pattern detection** — เก็บ log ว่าเด็กผิดแพตเทิร์นไหนซ้ำ (เช่น ลืม -s พหูพจน์, สับสน he/she) แล้ว generate แบบฝึกหัดเจาะจุดนั้นโดยเฉพาะ โดยใช้โมเดลภาษาช่วยสร้าง

## 5. Gamification (อ้างอิง Duolingo แล้วปรับให้เหมาะกับเด็กเล็ก)

| กลไก | รายละเอียด | หมายเหตุ |
|---|---|---|
| XP + Level | ได้ XP ทุกด่าน | |
| Streak (ไฟต่อเนื่อง) | เล่นทุกวันไฟไม่ดับ + Streak Freeze 2 ชิ้น/เดือน | ปรับให้ใจดีกว่า Duolingo — เด็กไม่ควรเสียใจเพราะ streak หลุด |
| หัวใจ/พลัง | **ไม่เอา** ระบบหัวใจที่บังคับรอหรือจ่ายเงิน | เป็น dark pattern ไม่เหมาะกับเด็กและผิดจุดประสงค์การศึกษา |
| มาสคอตสัตว์เลี้ยง | เลี้ยงสัตว์ที่โตขึ้นและแต่งตัวได้ด้วยเหรียญจากการเรียน | แรงจูงใจที่ได้ผลกับเด็กมากกว่า leaderboard |

| ลีกรายห้องเรียน | แข่งกันเฉพาะในห้องเรียน ไม่ใช่ทั่วโลก | ปลอดภัยและครูคุมได้ |
| Daily goal เลือกได้ | เบา 3 นาที / ปกติ 7 นาที / จัดเต็ม 15 นาที | ให้เด็กกับผู้ปกครองเลือกร่วมกัน |

## 7. Tech Stack ที่เสนอ และเหตุผล

| ชั้น | เลือก | เหตุผล |
|---|---|---|
| Framework | **Next.js 16.4 (App Router) + TypeScript** — ติดตั้งแล้ว | ต้องมี backend เพื่อซ่อน API key (ห้ามเรียกโมเดลภาษาจากเบราว์เซอร์ตรง ๆ) + สตรีมคำตอบได้ + deploy ง่าย |
| UI | **Tailwind CSS v4** + component ที่เขียนเอง (ไม่ใช้ shadcn/ui ฝั่งเด็ก — ดู [ADR-0004](adr/0004-custom-ui-components.md)) | เร็ว คุม design token ได้ ทำธีมเด็ก (สีสด ปุ่มใหญ่ มุมโค้ง) ได้สบาย |
| Animation | **Framer Motion** + Lottie สำหรับมาสคอต | ความ "ฉ่ำ" ของแอปเด็กมาจาก animation feedback เป็นเรื่องจำเป็น ไม่ใช่ของฟุ่มเฟือย |
| Drag & Drop | **dnd-kit** | รองรับ touch + คีย์บอร์ด + screen reader ซึ่งเกมจับคู่และเรียงประโยคต้องใช้ |
| State | Zustand + TanStack Query | เบา เข้าใจง่าย |
| Validation | Zod | ใช้ validate ทั้ง API และ structured output จากโมเดลภาษา |
| DB / Auth / Storage | **Supabase** | Postgres จริง + RLS + auth + storage ครบในที่เดียว free tier พอสำหรับงานสัมมนาและการนำร่อง |
| LLM | **Gemini API** — `gemini-3.1-flash-lite` สำหรับแชท (~1 วิ) ถอยไป `gemini-3.5-flash` เมื่อตัวแรกล่ม | เลือกจากที่วัดจริงบนโควตาฟรี รุ่นใหม่กว่าช้าเกินไปสำหรับเด็ก (ดู ADR-0006) |

## 9. Pipeline เสียง (ส่วนที่ยากที่สุดทางเทคนิค)

### 9.1 เส้นทางข้อมูลของ "แชทด้วยเสียง"

```
เด็กกดไมค์ --MediaRecorder(webm/opus)--> /api/stt --> ข้อความที่เด็กพูด
                                                            |
                                                            v
                                                 /api/chat (Gemini)
                                                            |
                              แบ่งเป็นประโยค <---------------+
                                     |
                                     v
       เล่นเสียงทีละประโยค <-- /api/tts (สตรีม + แคช)
```

**งบเวลา (latency budget) เป้าหมายต่ำกว่า 1.5 วินาที** ก่อนเด็กจะได้ยินเสียงตอบคำแรก:
STT ประมาณ 400–800 ms · โมเดลภาษาตอบครบ ~1000–1300 ms · TTS first chunk 200–400 ms

เทคนิคสำคัญคือ **ไม่รอโมเดลพูดจบ** ให้ตัดประโยคแรกส่งเข้า TTS ทันที (sentence-level pipelining) — ยังไม่ได้ทำ เพราะเทิร์นแชทตอนนี้รอ JSON ครบก้อน (เหตุผลใน ADR-0006)

### 9.2 การให้คะแนนออกเสียง

ส่งไฟล์เสียงพร้อม "ข้อความที่ควรพูด" ไปที่ Pronunciation Assessment แล้วได้กลับมาเป็น accuracy / fluency / completeness / prosody พร้อมคะแนนรายหน่วยเสียง จากนั้นแปลงเป็นดาว 1–3 ดวง และ **ฟีดแบ็กภาษาไทยที่เด็กเข้าใจ** เช่น "เสียง th ลองเอาลิ้นแตะฟันหน้าเบา ๆ นะ" โดยทำตาราง map phoneme → คำแนะนำไทย ไว้แบบ static

### 9.3 กลยุทธ์คุมต้นทุน

| จุด | วิธี |
|---|---|
| TTS คำศัพท์/ประโยคในบทเรียน | **pre-generate ตอน seed** เก็บเป็น mp3 ใน Storage ทำให้ต้นทุน runtime = 0 |
| TTS คำตอบแชท (คาดเดาไม่ได้) | สตรีม + แคชตาม hash ของข้อความ (คำตอบซ้ำ ๆ เช่นคำทักทายจะโดนแคช) |
| LLM แชท | `haiku-5-5` + จำกัด max_tokens + system prompt สั้น + prompt caching |
| LLM ตรวจงาน | `sonnet-5-5` เรียกเฉพาะคำตอบปลายเปิด (ข้อปรนัยตรวจด้วยโค้ด ไม่เรียก LLM) |
| STT | ตัด silence ฝั่ง client ก่อนส่ง + จำกัดความยาวคลิปไม่เกิน 15 วินาที |

> ตัวเลขราคาจริงของแต่ละผู้ให้บริการ ผมจะไปดึงจากเอกสารล่าสุดมายืนยันตอนที่คุณเลือกผู้ให้บริการแล้ว (ยังไม่อยากใส่เลขที่ไม่ได้เช็ค) — Azure มี free tier F0 ที่พอสำหรับช่วงพัฒนาและเดโม

## 10. ออกแบบ AI Chat Buddy ให้ปลอดภัยและสอนได้จริง

**System prompt มี 6 ส่วนบังคับ**

1. บทบาท: เพื่อนสัตว์ชื่อ Milo คุยกับเด็กอายุ {age} ปี
2. เพดานภาษา: ใช้คำในระดับ {CEFR} เท่านั้น ประโยคไม่เกิน {n} คำ ไม่ใช้สำนวนยาก
3. วินัยการสอน: ตอบ 1–2 ประโยค **แล้วถามกลับ 1 คำถามเสมอ** เพื่อไม่ให้บทสนทนาตาย
4. การแก้ผิด: ไม่ดุ ใช้วิธี recast คือทวนประโยคที่ถูกให้ฟังอย่างเป็นธรรมชาติ
5. scaffold ไทย: ระดับ Pre-A1/A1 แทรกไทยในวงเล็บได้ A2 ขึ้นไปห้ามใช้ไทยเว้นแต่เด็กขอ
6. guardrail: ไม่ถามข้อมูลส่วนตัว ไม่พูดเรื่องรุนแรง/การเมือง/ศาสนา และถ้าเด็กเล่าเรื่องน่าห่วง (ถูกทำร้าย ทำร้ายตัวเอง) ให้ตอบอย่างอบอุ่นและ **ยกธงให้ผู้ปกครองหรือครูเห็น**

**Structured output ทุกเทิร์น** นอกเหนือจากข้อความที่เด็กเห็น:

```json
{
  "reply": "...",
  "objective_met": true,
  "words_used": ["cat", "big"],
  "errors": [{ "type": "plural_s", "child_said": "two cat", "correct": "two cats" }],
  "safety_flag": null,
  "suggested_followups": ["...", "..."]
}
```

ข้อมูลชุดนี้ใช้ให้ XP, ป้อนกลับเข้า SRS, และสร้างรายงานให้ครู ทำให้แชทไม่ใช่แค่คุยเล่น แต่ป้อนข้อมูลกลับเข้าเอนจินการเรียน

**ปุ่มช่วยเหลือสำหรับเด็กที่ยังพูดไม่ได้**: มีคำตอบสำเร็จรูป 3 ตัวเลือกให้กดพูดตาม เพราะเด็กอนุบาลต้องเริ่มจากการ "พูดตาม" ก่อน "พูดเอง"

### 10.1 หัวข้อคุย — หมวดใหญ่ ไม่ใช่หน่วยคำศัพท์

หน้าแชทเคยให้เลือกหัวข้อจาก **หน่วยคำศัพท์ทุกหน่วยในคลัง** ซึ่งตอนเขียนมีสิบหน่วย
จึงพอไหว พอคลังโตเป็น 121 หน่วย เมนูก็กลายเป็นปุ่มร้อยกว่าปุ่มที่เด็กเลือกไม่ถูก
และหลายหน่วยไม่ใช่เรื่องที่ใครจะชวนคุย — "คำกริยา B2 ชุด 4" ไม่ใช่หัวข้อสนทนา

ตอนนี้จัดเป็น **เก้าหมวด** ใน `src/lib/chat/topics.ts` โดยหนึ่งหมวดกินหลายหน่วย
ข้ามระดับ เช่น "คนและอาชีพ" รวมครอบครัว เพื่อน และอาชีพตั้งแต่ A1 ถึง C1
หมวดแรกคือ **"คุยอะไรก็ได้"** ซึ่งไม่ผูกกับหน่วยไหนเลยและสั่งให้ Milo ตามเด็ก
แทนที่จะลากกลับเข้าหัวข้อ — เป็นค่าเริ่มต้น เพราะเด็กเปิดหน้านี้มาเพื่อคุย
ไม่ได้มาเลือกหมวด

**เพดานระดับเป็นตัวกรองในโค้ด ไม่ใช่คำขอร้องใน prompt** — `topicWords()`
ตัดคำที่สูงกว่าระดับเด็กออกก่อนจะถึงโมเดล แล้ว prompt ค่อยย้ำอีกชั้น
เด็ก A1 จึงคุยเรื่องสัตว์ได้โดยไม่เจอ hedgehog ของ C1 มีเทสไล่ทุกหมวด
คูณทุกระดับคุมไว้ และมีเทสบังคับว่าหน่วยใหม่ทุกหน่วยต้องถูกจัดเข้าหมวด
ไม่งั้นมันจะหายไปจากหน้าแชทเงียบ ๆ

ตารางหมวดนี้ **ไม่ได้จัดหลักสูตรใหม่** แผนที่ด่านยังใช้หน่วยเดิมทุกหน่วย

### 10.2 เสียงของ Milo กับไมค์ในหน้าแชท

**เสียง** — เสียง default ของเครื่องเป็นเสียงผู้ใหญ่อ่านเรียบ ๆ ซึ่งเหมาะกับ
การอ่านคำศัพท์ให้ชัด แต่ไม่เหมาะกับตัวละครที่เด็กควรอยากคุยด้วย `MILO_VOICE`
จึงขอเสียงผู้หญิงถ้าเครื่องมี ดัน pitch เป็น 1.35 และช้าลงเล็กน้อย
**pitch เป็นตัวหลัก** เพราะใช้ได้ทุกเครื่อง ส่วนการเลือกเสียงขึ้นกับว่า
เครื่องนั้นมีเสียงอะไรติดมา ปุ่มลำโพงของการ์ดคำศัพท์ยังใช้เสียงอ่านชัดเหมือนเดิม

**ไมค์** — ใช้ตัวถอดเสียงตัวเดียวกับเกมพูดและโหมดอ่านออกเสียง (Web Speech API
ซึ่งใน Chrome คือบริการของ Google) เติมคำที่ถอดได้ลง **ช่องพิมพ์** ไม่ได้ส่งทันที
เพราะตัวถอดเสียงพลาดบ่อยกับเสียงเด็กและสำเนียงไทย ถ้าส่งอัตโนมัติเด็กจะงง
ว่าทำไม Milo ตอบเรื่องที่ตัวเองไม่ได้พูด และแก้ก่อนส่งไม่ได้

ไมค์ฟัง **ต่อเนื่อง 45 วินาที** ไม่ใช่โหมดคำเดียวที่ปิดทันทีที่เงียบ เพราะเด็กที่
กำลังนึกประโยคอังกฤษจะหยุดคิดกลางทางเสมอ แล้วไมค์จะตัดกลางประโยค —
เจอตอนผู้ใช้ทดสอบจริง เด็กกดหยุดเองได้ ตัวจับเวลาเป็นแค่กันค้าง

แต่ `continuous` อย่างเดียวไม่พอ เพราะเบราว์เซอร์ยังยิง `onend` เองเมื่อ
คิดว่าเงียบแล้ว ซึ่งเร็วกว่าที่เด็กนึกประโยคออก เพิ่มตัวเลือก
`silenceGraceMs` ที่ **เปิดฟังต่อเองเงียบ ๆ** จนกว่าจะเงียบครบตามกำหนด
หน้าแชทตั้งไว้ที่ **หกวินาที** ค่าเริ่มต้นเป็น 0 คือพฤติกรรมเดิม
เกมพูดกับโหมดอ่านออกเสียงจึงไม่เปลี่ยน

**พูดจบแล้วส่งเข้าแชทเลย ไม่ต้องกดส่งอีกที** ตอนแรกทำเป็นเติมลงช่องพิมพ์
ให้เด็กตรวจก่อน เพราะตัวถอดเสียงพลาดบ่อยกับสำเนียงไทย แต่ผู้ใช้ทดสอบแล้ว
บอกว่ามันขัดจังหวะการคุย — เด็กพูดจบแล้วยังต้องละมือไปกดปุ่มอีกครั้ง
ถ้าถอดผิด เด็กพูดใหม่ในเทิร์นถัดไปได้ ซึ่งเป็นสิ่งที่เกิดกับการคุยกับคนจริงอยู่แล้ว

**ความแม่นกับสำเนียงไทยปรับจากฝั่งเราไม่ได้** Web Speech API ไม่มีช่องบอกว่า
ผู้พูดเป็นคนไทย ที่ช่วยได้คือไม่ตัดกลางประโยค ให้เห็นคำที่ถอดได้ และแก้ก่อนส่ง
ถ้าต้องการแม่นกว่านี้ต้องย้ายไปบริการถอดเสียงแบบเสียเงิน ซึ่งเป็นคนละเรื่อง

### 10.3 Milo เคยถามวน และแก้ยังไง

ผู้ใช้ทดสอบแล้วเจอ Milo ถาม "Do you like a bear?" ต่อด้วย "Do you like a cat?"
ต่อด้วย "Do you like a dog?" สามเทิร์นติด และตอบ "I do not know." เวลาเด็กถาม
อะไรนอกบท ซึ่งเป็นการสัมภาษณ์ ไม่ใช่การคุย

ต้นเหตุคือกฎที่เขียนไว้เองว่า "ตอบสองประโยคแล้วถามกลับหนึ่งคำถาม" **ทุกเทิร์น**
โมเดลจึงหยิบรูปคำถามที่ง่ายที่สุดมาใช้ซ้ำ แก้สามชั้นเรียงจากอ่อนไปแข็ง

1. **สั่งให้หมุนรูปคำถาม** พร้อมรายการรูปอื่น และอนุญาตให้หนึ่งในสามเทิร์น
   จบโดยไม่ต้องถาม เพราะการบังคับถามทุกเทิร์นคือต้นเหตุ
2. **ส่งคำถามเก่ากลับเข้า prompt** (`recentQuestionsFrom`) เพราะโมเดลไม่ได้จำ
   ว่าตัวเองถามอะไรไปแล้ว การสั่งลอย ๆ ว่า "อย่าถามซ้ำ" จึงไม่มีผล
3. **ห้ามคำขึ้นต้นที่ใช้ไปแล้ว** (`questionOpenings`) เพราะข้อ 2 กันได้แค่
   ประโยคที่ซ้ำคำต่อคำ ไล่ทดสอบจริงทั้งเก้าหมวดแล้วยังเหลือสี่หมวดที่ถาม
   "Do you like ..." สองครั้งด้วยคำลงท้ายต่างกัน ข้อนี้เป็นกฎที่เทียบได้ตรงตัว
   ไม่ต้องให้โมเดลตีความเอง

วัดผลด้วยการคุยจริงหกเทิร์นทั้งเก้าหมวด สองระดับ (A1 และ B1) แล้วดูว่าคำขึ้นต้น
ของคำถามซ้ำกันไหม — **ก่อนแก้ข้อ 3 ซ้ำสี่จากเก้าหมวด หลังแก้เหลือศูนย์ทั้งสองระดับ**
เทสหน่วยคุมได้แค่ว่าคำสั่งอยู่ใน prompt จริง ไม่ได้บอกว่าโมเดลทำตาม
การวัดแบบนี้จึงต้องทำซ้ำทุกครั้งที่แก้ prompt

**ข้อควรระวังตอนวัด**: ยิงรัว ๆ จะโดนจำกัดอัตราจากฝั่งโมเดล แล้วผลออกมาเป็น
"ล้ม" หลายหมวด ซึ่งอ่านเหมือนเนื้อหามีปัญหาทั้งที่เป็นเรื่องความเร็วล้วน ๆ
ต้องเว้นจังหวะและลองใหม่ก่อนจะสรุปว่าหมวดไหนพัง

### 10.3.1 รอบที่สอง — ไม่ถามซ้ำแล้ว แต่ยังหนีเรื่อง

ผู้ใช้ทดสอบต่อแล้วเจออาการคนละอย่างกับการถามซ้ำ: เด็กพิมพ์ว่า
"Sorry, I mean USA country." แล้ว Milo ตอบว่า "I see. Tell me about green trees."
คือ **เปลี่ยนเรื่องหนีไปหาคำในรายการคำศัพท์** ซึ่งการวัดคำขึ้นต้นคำถามจับไม่ได้
เพราะคำถามก็ยังไม่ซ้ำจริง ๆ

ต้นเหตุคือบรรทัดที่เขียนว่า "Prefer these words" พร้อมรายการคำสี่สิบคำ
โมเดลอ่านว่าเป็น **เช็กลิสต์ที่ต้องไล่ให้ครบ** ไม่ใช่เพดานว่าใช้คำไหนได้
จึงลากบทสนทนาไปหาคำแทนที่จะตอบเด็ก แก้สองที่

- เปลี่ยนถ้อยคำเป็น "เด็กรู้คำพวกนี้แล้ว จะใช้ก็ได้" และเติมว่า
  **"นี่คือรายการของที่พูดได้ ไม่ใช่รายการเรื่องที่ต้องพูดถึง"**
  พร้อมระบุว่าการลากคำที่เด็กไม่ได้พูดถึงเข้ามาคือเทิร์นที่ล้มเหลว
- เพิ่มกฎ 3a "อยู่กับเรื่องที่เด็กเพิ่งพูด" ไว้ **ก่อน** กฎเรื่องการถาม
  เพราะการตอบให้ตรงสำคัญกว่าการถามกลับ

และแก้กฎความปลอดภัยด้วย — เดิมห้ามคุยการเมือง ซึ่งโมเดลตีความกว้างจนเลี่ยง
คำถามเรื่องประเทศ ตอนนี้ระบุชัดว่า **ประเทศ เมือง อาหาร สัตว์ กีฬา อากาศ
ของที่อื่นไม่ใช่การเมือง** ที่ห้ามคือรัฐบาล การเลือกตั้ง สงคราม และผู้นำ

วัดด้วยการโยนเรื่องที่ไม่มีในคลังคำเลย ("I went to Japan with my family."
ตามด้วย "Sorry, I mean Japan.") เข้าไปทั้งเก้าหมวด แล้วดูว่าคำตอบพูดถึง
เรื่องนั้นไหม — **เก้าจากเก้าหมวดอยู่กับเรื่อง** ไม่มีหมวดไหนหนีไปหาคำในรายการ

### 10.4 เสียง Kokoro ที่รันในเครื่อง

เสียงที่ติดมากับเบราว์เซอร์คุณภาพขึ้นกับเครื่องและฟังเหมือนระบบประกาศ
[Kokoro](https://huggingface.co/hexgrad/Kokoro-82M) เป็นโมเดลโอเพนซอร์ส
**Apache-2.0** ที่ให้เสียงเป็นธรรมชาติกว่ามาก และรันในเครื่องผู้ใช้ได้เลย
ผ่าน `kokoro-js` (Apache-2.0 เช่นกัน) ไม่ต้องมีเซิร์ฟเวอร์และไม่มีค่าใช้จ่ายต่อครั้ง

**ราคาที่ต้องจ่ายคือครั้งแรกต้องโหลดโมเดลราว 88 MB** (`model_quantized.onnx`)
จึง **เปิดเองอัตโนมัติไม่ได้** ต้องให้ผู้ใช้กดเลือก เพราะเด็กที่ใช้เน็ตมือถือ
จะเสียค่าเน็ตโดยไม่รู้ตัว และต้องถอยกลับไปใช้เสียงเบราว์เซอร์เสมอเมื่อยัง
โหลดไม่เสร็จหรือโหลดไม่สำเร็จ — เด็กต้องได้ยินเสียงตอบทุกครั้ง ไม่ใช่เงียบ
เพราะโมเดลยังโหลดอยู่ หลังโหลดครั้งแรกเบราว์เซอร์แคชไว้ ใช้ออฟไลน์ได้

**ต้องตัดคำแปลไทยในวงเล็บออกก่อนอ่าน** (`speakableText`) เพราะระดับ Pre-A1
กับ A1 อนุญาตให้ Milo ใส่คำแปลไทย เช่น "I am a big bear (หมี)." ซึ่งดีสำหรับ
การอ่าน แต่ตัวอ่านภาษาอังกฤษอ่านอักษรไทยไม่ได้ บนจอยังเห็นคำแปลเหมือนเดิม

(Fierce Warrior)** รหัส `SOYHLrjzK2X1ezoPC6cr` กำหนดไว้ใน
`src/app/api/tts/route.ts`

เรียกผ่าน API route ของเราเองเท่านั้น **คีย์ห้ามโผล่ในเบราว์เซอร์** เหมือน
`GEMINI_API_KEY` เพราะ ElevenLabs คิดเงินตามจำนวนตัวอักษร ถ้าคีย์หลุด
คนอื่นเผาโควตาเราได้ ฝั่งหน้าเว็บรู้แค่ว่าส่งข้อความไปแล้วได้ไฟล์เสียงกลับมา

ทางบนใช้ไม่ได้

จำกัดความยาวข้อความที่ 500 ตัวอักษรเท่าข้อความแชท และให้เบราว์เซอร์แคช

**ยังไม่มีโควตารายวันเหมือน route ของแชท** ซึ่งควรมีก่อนเปิดให้คนอื่นใช้

## 12. ความปลอดภัยเด็ก และ PDPA (ห้ามข้าม เพราะเป็นแอปสำหรับเด็ก)

- เก็บข้อมูลเด็กให้น้อยที่สุด: **ไม่ขอชื่อจริง นามสกุล รูปถ่าย หรืออีเมลของเด็ก** ใช้ชื่อเล่นกับ avatar
- บัญชีเด็กสร้างผ่านผู้ปกครองหรือครูเท่านั้น (class code / parent-linked)
- คลิปเสียงเด็ก: ประมวลผลแล้ว **ลบทันที** ยกเว้นผู้ปกครองกดยินยอมให้เก็บไว้ดูพัฒนาการ
- ไม่มีแชทระหว่างผู้ใช้ ไม่มีโปรไฟล์สาธารณะ ไม่มีโฆษณา ไม่มี tracker ของบุคคลที่สาม
- บันทึกฐานทางกฎหมายและคำยินยอมตาม PDPA ไทย พร้อมหน้า privacy ภาษาไทยที่ผู้ปกครองอ่านรู้เรื่อง
- Safety flag จากแชทส่งขึ้นแดชบอร์ดครู/ผู้ปกครอง
