## ทาง 1 — ให้คนในวง Wi-Fi เดียวกันลอง

เหมาะกับการนำเสนอในห้อง ให้เพื่อนร่วมงานหรือครูลองบนมือถือตัวเอง

```bash
npm run build
npx next start -p 3100 -H 0.0.0.0
```

`-H 0.0.0.0` สำคัญ ถ้าไม่ใส่ Next.js จะรับเฉพาะเครื่องตัวเอง

จากนั้นหาที่อยู่ของเครื่องในวง แล้วให้คนอื่นเปิดจากมือถือ

```bash
node -e "const o=require('os');for(const l of Object.values(o.networkInterfaces()).flat())if(l.family==='IPv4'&&!l.internal)console.log('http://'+l.address+':3100')"
```

**ถ้าเปิดไม่ขึ้นจากเครื่องอื่น** มักเป็นไฟร์วอลล์ของ Windows บล็อกไว้ —
ครั้งแรกที่รันจะมีหน้าต่างถามว่าอนุญาตไหม ต้องกดอนุญาตสำหรับเครือข่ายส่วนตัว

**ข้อควรรู้**: เครื่องที่รันต้องเปิดทิ้งไว้ และคนที่เข้ามาใช้โควตา
Gemini กับ ElevenLabs ของเจ้าของเครื่อง ซึ่งมีตัวกั้นอยู่ที่
**แชท 40 เทิร์น และฟังเสียง 120 ครั้ง ต่อเครื่องต่อวัน**

## ทาง 2 — เปิดสาธารณะบน Vercel

### ก่อนเริ่ม ต้องมี

- บัญชี GitHub และบัญชี Vercel (สมัครฟรี)
- คีย์ `GEMINI_API_KEY` และ `ELEVENLABS_API_KEY` ที่ใช้งานได้

### ⚠ Vercel CLI ใช้บนเครื่องนี้ไม่ได้

`npx vercel` ทุกคำสั่งพังด้วย

```
TypeError: Cannot convert argument to a ByteString because the character
at index 0 has a value of 3609 which is greater than 255
```

3609 คือรหัสของตัว "น" — ชื่อเครื่องนี้เป็นภาษาไทย ("นิติภูมิ") และ CLI
เอาไปใส่ใน HTTP header ซึ่งรับได้แต่ ASCII ลองแก้ด้วยการเปลี่ยน
`COMPUTERNAME` และ patch `os.hostname()` แล้วก็ยังพัง เพราะค่ามาจากที่อื่น

**ให้ใช้ทาง GitHub + หน้าเว็บ Vercel แทน ไม่ต้องใช้ CLI เลย**
(ถ้าอยากใช้ CLI จริง ๆ ต้องเปลี่ยนชื่อเครื่องใน Windows เป็นอักษรอังกฤษก่อน)

### ขั้นตอน

1. **สร้าง repo บน GitHub แล้วพุชขึ้นไป** — โปรเจกต์นี้ยังไม่มี remote

   ```bash
   git remote add origin https://github.com/<ชื่อผู้ใช้>/<ชื่อ repo>.git
   git push -u origin master
   ```

   `.env.local` ถูก gitignore ไว้แล้ว คีย์จึงไม่ขึ้นไปด้วย — **อย่าแก้จุดนี้**

2. **นำเข้าโปรเจกต์ใน Vercel** — New Project แล้วเลือก repo นั้น
   Vercel ตรวจเจอว่าเป็น Next.js เองและตั้งค่า build ให้ ไม่ต้องแก้อะไร

3. **ใส่ตัวแปรสภาพแวดล้อม** ที่ Settings → Environment Variables

   | ชื่อ | ค่า |
   |---|---|
   | `GEMINI_API_KEY` | คีย์จาก Google AI Studio |
   | `ELEVENLABS_API_KEY` | คีย์จาก elevenlabs.io |

   ใส่ให้ครบทั้ง Production และ Preview ไม่งั้นลิงก์พรีวิวจะเสียงไม่ออก

4. **Deploy** แล้วรอ build เสร็จ จะได้ลิงก์ `https://<ชื่อ>.vercel.app`

### เช็กหลัง deploy

- เปิดหน้าแรก เห็นป้ายระดับครบหกระดับ
- เปิด `/credits` เห็นแหล่งข้อมูลครบห้าแหล่ง
- เปิด `/chat` แล้วพิมพ์คุย ต้องได้คำตอบและได้ยินเสียง
  (ถ้าเงียบแปลว่า `ELEVENLABS_API_KEY` ยังไม่เข้า แต่แอปยังใช้ได้
  เพราะถอยไปใช้เสียงของเบราว์เซอร์เอง)
- เปิดจากมือถือจริงหนึ่งเครื่อง เพราะโหมดพูดกับอ่านออกเสียงต้องใช้ไมค์

## สิ่งที่ยังไม่พร้อมสำหรับการเปิดสาธารณะ

ทั้งสามข้อนี้ไม่ได้ขวางการให้คนในห้องลอง แต่ขวางการเปิดให้คนทั่วไป

### 1. สัญญาอนุญาตยังไม่ได้ตัดสิน

หน้า `/credits` ของแอปเองเขียนไว้ว่า **"ตอนนี้จึงยังไม่ควรเผยแพร่แอปนี้
ต่อสาธารณะ จนกว่าจะระบุให้ชัดว่าส่วนไหนอยู่ใต้สัญญาอะไร"**

เหตุผล — เนื้อหาสี่ในห้าแหล่งเป็น CC BY-SA 4.0 ซึ่งบังคับว่างานดัดแปลง
ต้องเผยแพร่ด้วยสัญญาเดียวกัน ส่วน CEFR-J ระบุว่าการใช้เชิงพาณิชย์ต้องติดต่อ
Tono Laboratory ก่อน และตัวแอปเองยังไม่ได้เลือกสัญญาอนุญาตของตัวเอง

**การให้คนลองใช้ฟรีไม่ใช่การใช้เชิงพาณิชย์** แต่ควรตัดสินใจเรื่องสัญญา
ของตัวแอปก่อนจะวางลิงก์สาธารณะ

### 2. ใครมีลิงก์ก็ใช้โควตาของเราได้

ไม่มีระบบล็อกอิน ตัวกั้นที่มีคือโควตารายวันต่อเลขไอพี ซึ่ง
**กันการใช้ผิดปกติแบบง่าย ๆ ได้ แต่กันคนตั้งใจเจาะไม่ได้** เพราะเปลี่ยนไอพีได้

### 3. ตัวนับโควตาหายเมื่อรีสตาร์ต

เก็บในหน่วยความจำของโปรเซส บนโฮสต์แบบ serverless แต่ละอินสแตนซ์นับแยกกัน
เพดานจริงจึงหลวมกว่าตัวเลขที่ตั้งไว้มาก ต้องย้ายไปนับในฐานข้อมูล
(ภารกิจ E6) ก่อนจะถือว่ากันได้จริง

### ถ้าจะเปิดสาธารณะทั้งที่ยังไม่แก้สามข้อนี้

อย่างน้อยควร **ตั้งงบจำกัดในบัญชีผู้ให้บริการทั้งสองเจ้า** และ
**ใช้คีย์คนละตัวกับที่ใช้พัฒนา** เพื่อให้ยกเลิกได้โดยไม่กระทบเครื่องตัวเอง
