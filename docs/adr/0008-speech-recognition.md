# ADR-0008 — ตรวจการพูดด้วยตัวถอดเสียงของเบราว์เซอร์ และวัด "ฟังออกไหม" ไม่ใช่ "สำเนียงตรงไหม"

วันที่: 2 พ.ย. 2026 · สถานะ: ใช้อยู่ · ต่อจาก ADR-0003 (ชั้น adapter ของเสียง)

## บริบท

โจทย์ของเฟส P3 คือ "ฝึกพูดจนใช้สื่อสารได้จริง" และรายการงานเดิม (T306)
เขียนไว้ว่าต้องได้คะแนนออกเสียง 4 มิติพร้อมคะแนนรายหน่วยเสียง

ตัวเลือกที่มีจริงตอนนี้มีสองทาง:

| ทาง | ให้อะไร | ต้นทุน |
|---|---|---|
| Web Speech API ของเบราว์เซอร์ | ข้อความที่ถอดได้ + ตัวเลือกสำรอง | ฟรี ไม่ต้องมีบัญชี |
| บริการ pronunciation assessment (เช่น Azure) | คะแนนรายหน่วยเสียง 4 มิติ | ต้องมีบัญชีและจ่ายต่อนาที |

โปรเจกต์นี้ยังไม่มีบัญชีผู้ให้บริการที่ต้องจ่ายเงิน และ ADR-0006 ตั้งหลักไว้แล้ว
ว่าของที่เด็กต้องใช้ไม่จำกัดจำนวนครั้งต้องอยู่บนโควตาฟรีให้ได้ก่อน

## การตัดสินใจ

**1. ใช้ตัวถอดเสียงของเบราว์เซอร์ และเปลี่ยนคำถามที่ด่านนี้ถาม**

ไม่ดัดข้อความที่ถอดได้ให้กลายเป็น "คะแนนออกเสียง" ปลอม ๆ เพราะตัวเลขที่
สร้างจากข้อมูลที่ไม่มีจะทำให้ทั้งเด็กและครูเชื่อสิ่งที่ไม่จริง
ด่านนี้ตอบคำถามว่า **"พูดแล้วเครื่องฟังออกว่าเป็นคำนี้ไหม"**
ซึ่งเป็นตัวแทนที่ซื่อสัตย์ของ "คนอื่นฟังออกไหม" และตรงกับเป้าหมายของแอป
มากกว่าการเทียบสำเนียงกับเจ้าของภาษาทีละหน่วยเสียง

**2. ยอมรับคำตอบจากทุกตัวเลือกที่บริการคืนมา ไม่ใช่แค่ตัวแรก**

ขอ 5 ตัวเลือก (`maxAlternatives`) และผ่านถ้าตัวใดตัวหนึ่งตรง เพราะอันดับของ
ตัวเลือกมาจากความถี่ของคำในภาษาอังกฤษทั่วไป ไม่ใช่ความใกล้เคียงของเสียง
เสียงเด็กไทยพูดอังกฤษอยู่นอกข้อมูลที่โมเดลพวกนี้ฝึกมา คำที่ออกเสียงถูกจึง
ไปอยู่อันดับรองได้บ่อย — ทดสอบจริงแล้วว่าเป้าหมาย `red` โผล่เป็นตัวเลือกที่สอง
ขณะที่ตัวแรกเป็น `bread`

**3. ยอมรับคำพ้องเสียงด้วยตารางในโค้ด** (`HOMOPHONES` ใน `judge.ts`)

ตัวถอดเสียงคืน *ตัวสะกด* ไม่ใช่ *เสียง* เด็กที่พูด `two` ถูกเป๊ะจะได้
ข้อความกลับมาว่า `to` หรือ `too` ตามที่โมเดลภาษาเดา การนับว่าผิดคือการ
ลงโทษเด็กที่ออกเสียงถูก ตารางเก็บเฉพาะคู่ที่เสียงเหมือนกันจริงในสำเนียง
General American ที่แอปใช้ และมีเทสบังคับว่าคู่ที่อยู่ในคลังคำทั้งคู่
ต้องยอมรับกันสองทาง

**4. ถอดเสียงไม่สำเร็จ ≠ เด็กพูดผิด**

ไมค์ถูกปฏิเสธ เน็ตหลุด หรือไม่ได้ยินเสียง จะ**ไม่บันทึกผล**และ**ไม่นับ
จำนวนครั้งที่ลอง** เพราะดาวความชำนาญที่เพี้ยนไปกำหนดวันนัดทบทวนและความยาก
ของข้อต่อไปอีกนาน ข้อมูลผิดแพงกว่าข้อมูลที่ขาด

**5. คำแนะนำการออกเสียงเป็นแบบ "รู้ก่อน" ไม่ใช่ผลวินิจฉัย** (`hints.ts`)

เมื่อไม่มีคะแนนรายหน่วยเสียง เราวินิจฉัยไม่ได้ว่าเด็กพลาดเสียงไหน
ที่ทำได้คือดูคำอ่านของคำเป้าหมายว่ามีเสียงที่คนไทยมักพลาดอยู่ไหม
(ภาษาไทยไม่มีหน่วยเสียง /θ ð v z ʃ ʒ dʒ/ และพยัญชนะท้ายคำของไทยมีแต่
เสียงกักที่ไม่ปล่อยลมกับเสียงนาสิก) แล้วสอนเสียงนั้นไว้ล่วงหน้า
เรียงลำดับตาม "พลาดแล้วคนฟังไม่เข้าใจมากที่สุด" จึงเอาเสียงท้ายคำที่หายไป
มาก่อนเสียงต้นคำที่เพี้ยน และโชว์ไม่เกิน 2 ข้อ

**6. ใช้การประมวลผลในเครื่องเมื่อทำได้ และบอกผู้ใช้เมื่อทำไม่ได้**

ค่าเริ่มต้นของ Chrome และ Safari คือ**ส่งเสียงไปถอดที่เซิร์ฟเวอร์ของผู้ให้
บริการเบราว์เซอร์** นี่คือแอปเด็ก เสียงเด็กเป็นข้อมูลส่วนบุคคล จึง:

- เรียก `SpeechRecognition.available({ processLocally: true })` ก่อนทุกครั้ง
  ถ้าพร้อมจะตั้ง `processLocally = true` ให้ประมวลผลในเครื่อง
- ถ้าไม่พร้อม **เขียนบอกบนหน้าจอตรง ๆ** ว่าเสียงถูกส่งออกนอกเครื่อง
  พร้อมปุ่มให้สั่งดาวน์โหลดชุดภาษา (`install()`) เพื่อเปลี่ยนมาตรวจในเครื่อง
- ไม่ตั้ง `processLocally = true` ทิ้งไว้โดยไม่เช็ค เพราะถ้าชุดภาษายังไม่ติดตั้ง
  `start()` จะล้มด้วย `language-not-supported` แล้วเด็กจะพูดไม่ได้เลย

**7. โหมดพูดต้องมีทางถอยทุกที่ที่เรียกใช้**

Firefox ยังไม่รองรับ (ซ่อนหลัง flag) `GameItem` จึงเช็คความรองรับฝั่ง
เบราว์เซอร์แล้วสลับไปโหมดอื่นของคำเดิม ส่วนหน้า `/speak` ที่เป็นการพูดล้วน
จะบอกตรง ๆ ว่าเล่นไม่ได้และต้องใช้เบราว์เซอร์ไหน ไม่สลับโหมดเงียบ ๆ
เพราะเด็กจะไม่รู้ว่าทำไมไม่ได้พูด

## ผลที่ตามมา

- ด่านพูดเล่นได้ฟรีไม่จำกัดจำนวนครั้ง ไม่ต้องมี API key
- **ยังไม่มีคะแนนรายหน่วยเสียง** T306 กับ T309 (Read Aloud ที่ต้องวัด
  ความคล่องและ WPM) จึงยังทำไม่ได้จริงด้วยเครื่องมือชุดนี้
- ตัวตัดสิน "ใจดี" เกินจริงได้: ถ้าเด็กพูด `work` เพี้ยนแต่เครื่องยังฟังออก
  ก็ผ่าน ซึ่งเป็นผลที่ยอมรับตามข้อ 1 — แอปนี้วัดความเข้าใจได้ ไม่ใช่สำเนียง
- เมื่อย้ายไปบริการที่ให้คะแนนรายหน่วยเสียง: เพิ่ม provider ใหม่ใต้
  `PronunciationProvider` (มี interface รออยู่แล้วตั้งแต่ ADR-0003)
  ตาราง `hints.ts` ใช้ต่อได้ เปลี่ยนแค่วิธีเลือกว่าจะโชว์ข้อไหน

## ที่ยังไม่ได้ทดสอบ

**การพูดจริงผ่านไมโครโฟน** — เบราว์เซอร์ที่ใช้ทดสอบบล็อกไมค์ไว้
ที่ทดสอบแล้วคือ: ตรรกะการตัดสินและตารางคำแนะนำ (เทส 270 ข้อ)
เส้นทางที่ไมค์ถูกปฏิเสธ (บนเบราว์เซอร์จริง — ขึ้นข้อความถูก ไม่นับครั้ง
ไม่บันทึกผล) และเส้นทางตัดสินผลถูก/ผิดด้วยตัวถอดเสียงปลอมที่ฉีดเข้าไป
**ต้องมีคนลองพูดจริงก่อนปล่อยถึงเด็ก**
