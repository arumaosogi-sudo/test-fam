# ADR-0001 — เลือก Next.js + Supabase + Vercel

วันที่: 1 พ.ย. 2026 · สถานะ: ใช้อยู่

## บริบท

ต้องสร้างเว็บแอปเรียนภาษาอังกฤษสำหรับเด็ก ที่มีทั้งเกม การเรียก LLM
การแปลงเสียงเป็นข้อความ และการเก็บความคืบหน้าของผู้เรียนรายคน

## การตัดสินใจ

- **Next.js (App Router) + TypeScript** — จำเป็นเพราะต้องมีฝั่งเซิร์ฟเวอร์เพื่อเก็บ
  API key ไว้ให้มิดชิด และต้องสตรีมคำตอบจาก LLM ทีละ token
- **Supabase** — ได้ Postgres จริง, RLS, auth และ storage ในที่เดียว ไม่ต้องประกอบเอง
- **Vercel** — deploy ตรงจาก repo ได้ preview URL ต่อ branch

## ทางเลือกที่ไม่เลือก และเหตุผล

| ทางเลือก | เหตุผลที่ไม่เลือก |
|---|---|
| Vite + React ล้วน (SPA) | ไม่มีฝั่งเซิร์ฟเวอร์ ถ้าจะเรียก Claude ต้องวาง key ไว้ในเบราว์เซอร์ซึ่งเท่ากับแจก key |
| Firebase | query เชิงสัมพันธ์ (ความคืบหน้ารายคำ ต่อสกิล ต่อห้องเรียน) ทำบน Postgres ง่ายกว่ามาก |
| Cloudflare Workers + D1 | ใช้ได้และถูกกว่า แต่ทีมคุ้นเคย Postgres น้อยกว่า และ ecosystem auth ยังไม่พร้อมเท่า Supabase |

## ผลที่ตามมา

- ค่าใช้จ่ายขึ้นกับ 3 ก้อนคือ LLM, บริการเสียง และ Supabase/Vercel
- ต้องระวังไม่ให้ logic การให้คะแนนไปอยู่ฝั่ง client เพราะเด็กโตแก้คำตอบได้
