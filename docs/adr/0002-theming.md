# ADR-0002 — ธีมผ่าน semantic token ไม่ใช้ `dark:` variant

วันที่: 1 พ.ย. 2026 · สถานะ: ใช้อยู่

## บริบท

แอปต้องรองรับธีมสว่างและมืด และต่อไปอาจต้องมีธีมคอนทราสต์สูงสำหรับเด็ก
สายตาไม่ดี ถ้าใช้วิธีปกติของ Tailwind คือเขียน `bg-white dark:bg-gray-900`
ทุก component จะต้องรู้เรื่องธีมเองทั้งหมด และเพิ่มธีมที่สามแทบไม่ได้

## การตัดสินใจ

1. ประกาศตัวแปรสีแบบ **semantic** (`--bg`, `--surface`, `--ink`, `--primary`,
   `--primary-edge`, `--primary-soft`, `--primary-ink`, …) ไม่ใช้ชื่อสีจริง
2. สลับค่าทั้งชุดที่ `:root` เมื่อ `data-theme="dark"` หรือเมื่อระบบตั้งเป็นมืด
3. map เข้า Tailwind ด้วย `@theme inline` ทำให้ใช้ `bg-primary` `text-ink` ได้ตามปกติ
4. **component ไม่เขียน `dark:` เลย**

## ผลที่ตามมา

- เพิ่มธีมใหม่ = เพิ่มบล็อก CSS หนึ่งบล็อก ไม่ต้องแก้ component
- ทุก variant ของปุ่มต้องกำหนด `--edge` (สีขอบล่างของปุ่มกดได้) ด้วย
- ข้อควรระวัง: ตัวแปร `*-ink` ต้องพลิกตามธีมด้วย เพราะสีพื้นที่สว่างในธีมมืด
  ต้องใช้ตัวอักษรสีเข้ม ไม่ใช่สีขาวเหมือนธีมสว่าง
